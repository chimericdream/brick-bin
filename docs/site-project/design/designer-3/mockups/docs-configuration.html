Configuration

Brick Bin reads its settings from environment variables, usually in a .env file next to the compose file. There are fourteen. Most installs set three or four.

On this page
  • The ones you must set
  • Server
  • Storage and limits
  • Catalog import
  • A typical .env

Restart the app after changing anything. Each variable name is a link you can share.

The ones you must set

Required variables
VariableWhat it doesDefault
DATABASE_URLPostgres connectionRequired
POSTGRES_PASSWORDDatabase password in the production compose fileSet it
TS_AUTHKEYTailscale key for the sidecar. Only needed on the Tailscale route.Set it

Server

Server variables
VariableWhat it doesDefault
APP_PORTPort published by the plain compose file3000
COOKIE_SECURESet true once Brick Bin is served over HTTPSfalse
AUTO_MIGRATEfalse skips database migrations on starttrue
APP_VERSIONOptional label shown in health checks and the import's User-AgentEmpty

Storage and limits

Storage variables
VariableWhat it doesDefault
DATA_DIRWhere covers, instruction PDFs and catalog images are kept./data
TRASH_RETENTION_DAYSDays a deleted item waits in the trash before it's deleted for good. 0 keeps it until an admin deletes it.30
INSTRUCTIONS_MAX_MBLargest instruction PDF the app will store, in megabytes200

Catalog import

These decide where catalog downloads may come from. Catalog data comes from Rebrickable, and the defaults point there. Downloads only ever go over HTTPS.

Catalog import variables
VariableWhat it doesDefault
REBRICKABLE_PAGE_FETCHtrue lets the import fetch the downloads page itself, instead of an admin pasting itfalse
REBRICKABLE_DOWNLOADS_PAGEAddress of the downloads pageRebrickable's page
REBRICKABLE_ALLOWED_ORIGINSOrigins the import may download from. HTTPS only.Rebrickable and its CDN
CATALOG_IMAGE_ORIGINThe only origin set covers are downloaded fromRebrickable's CDN
Leave the page fetch off for now

Until Rebrickable confirms that automated page reads are fine, keep REBRICKABLE_PAGE_FETCH at false and paste the page instead. The import tutorial shows how.

A typical .env

The recommended Tailscale install, with everything else left at its default:

.env
POSTGRES_PASSWORD=choose-something-long
DATABASE_URL=postgres://<user>:<password>@db:5432/<database>
TS_AUTHKEY=tskey-auth-…
COOKIE_SECURE=true

Variables used only by tests aren't listed here.
