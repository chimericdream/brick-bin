Hosting

The recommended home for Brick Bin, how it stays up to date, how much disk it wants, and how to back it up.

Proxmox and Docker

A Proxmox VM or LXC container with Docker is the recommended home. Either works; pick whichever you already know. Any other machine that runs Docker is fine for a try-out.

Tailscale and HTTPS

The production compose file includes a Tailscale sidecar. It joins your tailnet with TS_AUTHKEY and serves Brick Bin over HTTPS at:

Address
https://brick-bin.<your-tailnet>.ts.net

Only devices on your tailnet can reach it. Once it's served over HTTPS, set COOKIE_SECURE=true.

Running without Tailscale

Run the production compose file and open port 3000 (or whatever APP_PORT says). This is fine on a home network for a try-out. Without HTTPS, leave COOKIE_SECURE at false or you won't be able to sign in.

Updates

Watchtower checks for a new Brick Bin image every five minutes and restarts the app when there is one. Database migrations run on start unless AUTO_MIGRATE is false.

Postgres is never updated automatically

A major database upgrade needs a backup and a person paying attention, so Watchtower leaves Postgres alone.

Disk space

  • Catalog: several GB. The first import downloads about 6 GB of part images plus a data archive.
  • Database: a few hundred MB.
  • Instruction PDFs: tens of GB over time. Cap single files with INSTRUCTIONS_MAX_MB.

Covers, PDFs and catalog images live in DATA_DIR.

Backups

Back up three things:

  1. Database dumps. The catalog tables are skipped, because they can be imported again.
  2. Cover images.
  3. Instruction PDFs.

The downloaded catalog images are not backed up. They're large and Rebrickable still has them.

Example: check against your compose file
# Dump the database, skipping the catalog tables
docker compose exec db pg_dump -U <user> <database> \
  --exclude-table-data='<catalog tables>' > brick-bin-$(date +%F).sql

Restoring

  1. Start a fresh stack with the same .env.
  2. Load the database dump, then copy back the covers and PDFs.
  3. Run a catalog import again. Until you do, catalog searches come back empty and part pictures are missing.

Catalog data comes from Rebrickable.
