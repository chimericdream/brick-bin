Configuration

Brick Bin reads its settings from environment variables, usually in a .env file next to the compose file. Most have a sensible default.

All variables

Three need setting: DATABASE_URL, POSTGRES_PASSWORD and, on the Tailscale route, TS_AUTHKEY. Change the rest when you have a reason to. Restart the app after editing.

An example .env

For the recommended Tailscale setup, a working file can be this short:

.env
POSTGRES_PASSWORD=a-long-password-from-your-password-manager
DATABASE_URL=postgres://brickbin:a-long-password-from-your-password-manager@db:5432/brickbin
TS_AUTHKEY=tskey-auth-xxxxxxxxxxxx
COOKIE_SECURE=true
TRASH_RETENTION_DAYS=30

Never commit a .env file to a repository, and keep a copy with your backups.

The catalog settings

The four REBRICKABLE_* and CATALOG_* settings decide where catalog downloads may come from. The defaults point at Rebrickable and its CDN, and downloads only ever go over HTTPS.

Leave REBRICKABLE_PAGE_FETCH off for now. Until Rebrickable confirms automated page reads are fine, admins paste the downloads page into the app instead.

Catalog data comes from Rebrickable.
