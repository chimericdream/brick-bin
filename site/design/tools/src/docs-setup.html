Setup

From an empty machine to the first-visit screen. The recommended route uses Tailscale. There's a shorter one if you only want a look around.

{TOC}

Before you start

Brick Bin is a self-hosted app. You run it on your own server and reach it over your own network. You'll need:

  • A machine that runs Docker. We recommend a Proxmox VM or LXC.
  • A Tailscale account and an auth key, if you're following the recommended route.
  • Disk space: several GB for the catalog, a few hundred MB for the database, and tens of GB for instruction PDFs over time. Storage in detail.

Quick try-out, without Tailscale

To see Brick Bin before committing to anything, run the production compose file as it is and open port 3000.

Terminal
# in the folder that holds the compose file
POSTGRES_PASSWORD=choose-something-long docker compose up -d

# then open
http://<your-server>:3000

Fine for a look, not for keeps

This serves plain HTTP on your network. When you move to HTTPS, set COOKIE_SECURE to true.

Recommended install, with Tailscale

The full stack is four containers: the app, its own Postgres 17, a Tailscale sidecar that serves HTTPS, and Watchtower to keep the app image current. What each one does.

  1. Create a Proxmox VM or LXC and install Docker on it.
  2. Copy the compose file and .env.example onto the machine, and rename the second one to .env.
  3. Fill in the values that have no default, and turn on secure cookies:
    .env
    POSTGRES_PASSWORD=choose-something-long
TS_AUTHKEY=tskey-auth-…
COOKIE_SECURE=true
  4. Start it: docker compose up -d
  5. Open https://brick-bin.<your-tailnet>.ts.net from any device on your tailnet.

Every setting is listed in Configuration. Most installs only touch the three above.

Import the catalog

Brick Bin works without the catalog, but set search and part pictures need it. The first import downloads about 6 GB of part images plus a data archive from Rebrickable, and only runs when an admin starts it.

Tutorial: import the LEGO catalog

Staying up to date

Watchtower checks for a new app image every five minutes and swaps it in. Postgres is never auto-updated. Database migrations run when the app starts, unless you set AUTO_MIGRATE to false.
